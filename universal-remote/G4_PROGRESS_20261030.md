# BCP Universal Remote — G4 development continuity (30 Oct 2026)

## Verified baseline
- User's actual Samsung successfully runs BCP v1.1.1 (versionCode 15), paired over private HTTPS/HMAC with MBMPC.
- Android-to-Windows authenticated phone heartbeat validated in live field; 30-second foreground development polling validated.
- Single stable signed updater remains on MBMPC; no metered-network restriction.

## G4 Windows action gateway, separated staging
- Created authenticated G4 localhost Windows service with real absolute-path file browsing, text reading, system inventory, process list and audit.
- Mutations implemented in G4 localhost service: bounded file write, mkdir, pre-existing executable run, with per-operation short-lived single-use local Windows approval and HMAC approval seal.
- Validation: 17/17 core, 13/13 extra execution/backup, and 8/8 HTTPS/HMAC staging tests = **38/38 PASS**.
- Positive operation approvals were **simulated during lab tests**, not a person's actual click in Approval Center.
- A Windows desktop shortcut named "BCP G4 - Autoriser mes operations.cmd" was installed. Real user approval still to test.
- Source and tests pushed on branch feat/universal-remote-transport-20261030, commit b205385.

## Single-agent G2+G4
- Six read-only G4 routes added to G2 HTTPS/HMAC server: /v1/g4/{capabilities,system,processes,files/list,files/read,audit}.
- No remote shell/write/mkdir/commit exposed in G2. Integration staging tests: 10/10 PASS with 35s client timeout, while original G2 status continues to work.
- MBMPC has only 4 GB RAM. Staging measured system inventory 7s, home listing 6s, process enumeration 10s. Android advanced read timeout increased to 30s.
- First production restart **timed out after 18s** and triggered designed rollback to original G2. A subsequent field check confirmed the original service again listening on Wi-Fi, loopback and Tailscale. This is not a successful deployment of G4.
- Changed G4 initialization to lazy-on-first-authenticated-request, so startup does not require the costly new G4 private-state setup.
- A re-tested, successful production restart is still necessary before releasing the Android interface.

## Android feature staged (not yet signed/released)
- New v1.2.0 Android Files screen includes G4 Windows absolute-path browser and UTF-8 text reader, process list, system inventory; retains old USB test card separately.
- New routes are read-only and require the existing paired HMAC key over HTTPS/Tailscale. No admin/shell request exposed via Android UI.
- User should stay on v1.1.1 until production backend and Android CI are verified; avoid manual APK installation.
